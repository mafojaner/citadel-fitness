Premium (Fortress) & security hardening — September 2026

Launch gate: the production release goes to Play Console only once every row below is checked — not on a fixed date. Grounded in a code audit run 2026-08-14.
profiles privilege lockdown — applied to production Aug 17 via db push and confirmed by querying the live database, not by report: authenticated holds UPDATE on [avatar_url, name, preferences] only, the guard trigger is present, and the UPDATE policy now carries both using and with check. fortress_since is no longer client-writable.
Verified
Entitlement writes stay server-only: once billing exists, the entitlement column/table must only ever be written by a verified webhook or service role — never the client, even indirectly.
Open
backfill-welcome-emails: confirm it's deployed with the platform's default verify_jwt on (not --no-verify-jwt) — nothing in the function body itself blocks an unauthenticated call otherwise.
Open
Dependency audit: npm audit shows 14 high / 9 moderate, all in the build-tooling chain (uuid via expo config-plugins) — no runtime path in the shipped bundle, but clear it with a planned Expo SDK bump before submission.
Open
Play Data Safety form: fill it out against what the app actually collects and shares. Now covers two things, not one: the RLS-scoped tables, and the PostHog telemetry added Aug 19 — its TrackedEvent union is deliberately the complete, reviewable list of what leaves the device.
Open
Target SDK / permissions review: confirm Expo's managed defaults still satisfy Play's current target API requirement; the app requests no extra dangerous Android permissions today — keep it that way.
Open
Screen-reader pass on a real device: the Aug 20 work was verified in the web accessibility tree, which proves names and states exist but says nothing about how a TalkBack or VoiceOver user actually moves through a screen. Reading order, focus after navigation, and whether the tab bar is escapable can only be judged by listening. Roughly 18 pressables also still lack an explicit role — they have names, so they're usable, just announced as content rather than controls.
Open
Restore purchases + cancellation: tested end to end in sandbox before anyone can pay for real.
Open
Privacy policy: discloses neither the analytics added Aug 19 nor subscription billing. Telemetry is the nearer one — for EU users, non-essential analytics arguably needs consent rather than disclosure alone, and this stack is EU-oriented throughout (Supabase eu-west-1, Sentry .de, PostHog EU). The wrapper exposes opt-in/opt-out; whether to add a settings toggle is a product call, not plumbing.
Open
